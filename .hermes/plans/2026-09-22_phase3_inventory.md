### 重疊證據（三處實質重複）

1. **CIO 決策復盤出現兩次**：每日戰略審查（一/三 Part B）與週五深度審查（Part C）在分析同一份 `dashboard_decisions.json`，只是時間窗不同 → 週五那次是**第三次重複分析**同一批決策。
2. **資產配置分析出現三次**：週六再平衡評估（16:00）→ 週日動態檢討週報（19:00，相隔 1 天）→ 週五深度審查 Part A/B。三者都在講防守比重、TAA、資金輪動。
3. **防守/配置口徑已定案**（合併口徑 ≥60%），但三份報告各自重新推導 → 口徑漂移風險。

### 建議（合併方案）

- **合併 A**：週五深度審查 Part C（CIO 決策復盤）→ 改為「引用當週 CIO 審查摘要」，不再重跑。**省一次完整 LLM 分析**。
- **合併 B**：週五深度審查 ＋ 週日動態檢討週報 → 收斂成一個**「週度總審查」放週日 19:00**（一週資料最完整時點），版面＝資產防禦審計 ＋ 動態檢討（TAA/資金輪動）。**agent 任務 10 → 9**，且消除「相隔 5 天、口徑可能不一致」的兩份週報。
- **保留獨立**：週六再平衡評估（需週六盤後資料＋週末使用者可核准），但週日總審查改為「引用週六結論」，不重算。

## 二、日報時段鏈盤點

**早晨 9 個 job（07:00–09:10）**
```
07:00 morning_deploy（產出＋推送＋git）   ← 產出型
07:05 lj_structure_check（結構檢查）      ← 檢查型
07:10 dividend_tracker（配息掃描）        ← 產出型
07:30 gmail_triage（信箱整理）            ← 獨立管線
08:00 morning_batch（提醒/閉環/配息/簡報） ← 產出型
08:30 radar_weekly（僅週六）
08:35 penetration_monitor（穿透異常）     ← 監控型
08:45 us30y_monitor（US30Y 模式）         ← 監控型
09:00 cost_watch wallet / 09:10 alerts_morning
```
**判斷**：只有 `morning_deploy ＋ morning_batch` 是同一條「產出晨報」邏輯，可合併為 `morning.py`；
`lj_structure_check` / `penetration_monitor` / `us30y_monitor` 是**獨立告警源**，合併後一旦前段失敗會整批停 → **不合併**（告警獨立性優先）。

**夜間 5 個 job（22:00–22:50）**
```
22:00 evening_sync → 22:15 nightly_dashboard_sync → 22:30 cost close → 22:40 closeout_check → 22:50 maintenance nightly
```
**判斷**：`evening_sync ＋ nightly_dashboard_sync` 可合併為 `nightly_chain.py`（同為「產出＋同步」）。
**`closeout_check` 必須保持獨立** —— 它是稽核者，把稽核併進被稽核的鏈＝自己檢查自己（違反獨立性原則）。

## 三、agent 降階評估（每降一個＝該任務 LLM 成本歸零）

| 任務 | 需要 LLM 的理由 | 判定 |
|------|----------------|------|
| 轉貸簡報自動化 | prompt 只寫「執行 build_final.py＋通知」→ 無推理需求 | ✅ **可立即降為 no_agent** |
| 技能自我審查 | 需判斷技能內容是否過時 | ❌ 保留 |
| 週報／月報 | 需敘事與質化分析（使用者明確要求非模板） | ❌ 保留 |
| CIO 戰略審查 | 需對抗性推理 | ❌ 保留 |
| 緊急應變 ×2 | 需判讀新聞與寫分析 | ❌ 保留 |
| 每月真值日 | 需解析截圖、互動提醒 | ❌ 保留 |

→ **確定可降階 1 個**（轉貸簡報）；若合併 A/B 落地，週度總審查的資料彙整步驟也可腳本化，只剩敘事交給 LLM。
